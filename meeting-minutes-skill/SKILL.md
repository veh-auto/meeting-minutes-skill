# Meeting Minutes：会议转写 → 结构化纪要

## Overview

把原始会议转写文本转化为可直接使用的 Markdown 纪要，固定输出"会议议题""决议事项""行动项"三个部分。核心原则是**只提取文本中确实存在的信息**：人名、日期、结论均不得推测或编造，缺失信息用约定的占位词明确标记。

## Workflow

### Step 1：读取并清洗转写文本

- 接受直接粘贴的文本，或 `.txt` / `.md` / `.srt` / `.vtt` 等本地转写文件；若为文件，先读取全文。
- 带时间轴的转写（SRT/VTT）：去掉序号与时间戳，**保留说话人标签**（如 `张三：`），后续判断"本人认领"时需要用到。
- 合并被切断的句子，去除口头禅、重复语气词和明显的语音识别噪声，但不得改变原意。
- 超长文本按时间顺序分段处理，最后统一合并去重，保持原文叙述顺序。

### Step 2：按规则提取三类信息

提取前先阅读 `references/extraction_rules.md`，其中定义了议题、决议、行动项的判定标准和大量边界情况。要点：

- **会议议题**：围绕一个主题的完整讨论段落，按首次出现排序；同一主题的多处讨论合并为一个议题。
- **决议事项**：会议明确达成并认可的结论，如"决定/确定/通过/同意/采用"；提议、建议、待确认事项不算决议。
- **行动项**：会后要执行的具体任务，需包含动作，主体可以是"待指定"。决议描述"定了什么"，行动项描述"谁在什么时候做什么"，两者允许指向同一事项但不重复堆砌文字。

### Step 3：确定负责人与截止时间

- 负责人仅来自**明确指派**或**结合说话人标签可无歧义解析的本人认领**；无法唯一确定人名时写 `待指定`。
- 转写中出现"技术团队""产品组"等明确群体主体时原样填写；这属于原文信息，不算编造。
- 不得依据职务、部门、发言历史、常见姓名推断或补全人名；不得用"相关同学""负责人"等模糊说法替代 `待指定`。
- 截止时间：明确日期原样保留或标准化；相对时间（"下周三""月底"）仅在已知会议日期时换算并注明，否则保留原文并标注为相对时间；无明确时间写 `未明确`。绝不编造日期。
- 无负责人的行动项**仍然保留**，负责人字段填 `待指定`。

### Step 4：按模板输出 Markdown

- 使用 `assets/minutes_template.md` 作为输出结构，仅保留"会议议题""决议事项""行动项"三个二级章节，标题为"会议纪要"。
- 会议日期与参会人只有在转写文本明确给出时才写入标题下的元信息行，否则删除该行。
- 议题用有序列表（可附一句摘要），决议用有序列表（一条一个结论），行动项用表格，列为：序号、行动事项、负责人、截止时间。
- 某部分没有内容时写"本次会议未涉及。"，不要留空，也不要新增"其他事项""备注"等章节。
- 全程使用 Markdown，不输出 JSON、不附加解释性前言。

### Step 5：交付前自检

- [ ] 三个章节齐全，顺序正确，无多余顶级章节。
- [ ] 每个行动项都有负责人与截止时间字段；缺失值严格为 `待指定` / `未明确`。
- [ ] 没有任何原文不存在的人名、日期、决议或任务。
- [ ] 提议、讨论中的想法没有被误写成决议。
- [ ] Markdown 语法正确，表格可正常渲染。
